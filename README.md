# Lab: SQL Queries on AWS with CloudFormation

A hands-on lab that uses **AWS CloudFormation** to build a real SQL database on AWS
(**Amazon Aurora PostgreSQL Serverless v2**). You then learn SQL step by step against an
online-shop dataset: from `SELECT` basics through joins, CTEs, window functions,
transactions, views and indexes.

There are no servers, SSH or database passwords to manage. You run SQL from the **RDS Query Editor** in the
console or from your terminal through the **RDS Data API**. The database **pauses itself when
idle** (0 capacity units), so it costs almost nothing while you're not using it.

```
 ┌──────────────────────┐   aws cloudformation deploy    ┌──────────────── CloudFormation stack: sql-lab ────────────────┐
 │ cloudformation/      │ ─────────────────────────────▶ │  VPC 10.20.0.0/16                                             │
 │   sql-lab.yaml       │                                │   ├─ private subnet A (AZ 1) ┐                                │
 └──────────────────────┘                                │   ├─ private subnet B (AZ 2) ┴─ DB subnet group               │
                                                         │   └─ security group (no inbound rules)                        │
 ┌──────────────────────┐   HTTPS (RDS Data API)         │  Aurora PostgreSQL Serverless v2 cluster  (0 to 2 ACUs)       │
 │ Query Editor /       │ ─────────────────────────────▶ │   ├─ db.serverless writer instance                            │
 │ scripts/run_sql.py   │ ◀───── rows as JSON ────────── │   └─ database: shopdb                                         │
 └──────────────────────┘                                │  Secrets Manager: admin password (generated by RDS)           │
                                                         └───────────────────────────────────────────────────────────────┘
```

## What you will learn

**CloudFormation**
- Template anatomy: `Parameters`, `Resources`, `Outputs`, `Metadata`
- Intrinsic functions: `!Ref`, `!GetAtt`, `!Sub`, `!Select`, `!GetAZs`, `!Cidr`
- Deploying, updating with **change sets**, reading outputs and deleting a stack
- `DeletionPolicy`, and why databases need special care

**SQL (PostgreSQL)**
- `SELECT`, `WHERE`, `ORDER BY`, `LIMIT`, `DISTINCT`, `LIKE`, `IN`, `BETWEEN`, `NULL`
- Aggregates: `COUNT`, `SUM`, `AVG`, `GROUP BY`, `HAVING`, `FILTER`
- `INNER JOIN`, `LEFT JOIN`, anti-joins
- Subqueries, `EXISTS`, CTEs (`WITH`) and `CASE`
- Window functions: `RANK`, `ROW_NUMBER`, `LAG`, running totals
- `INSERT`, `UPDATE`, `DELETE`, `RETURNING`, constraints and transactions
- Views, indexes and `EXPLAIN`

## The dataset

```
customers (10) ──< orders (20) ──< order_items (32) >── products (15) >── categories (5)
```

| Table | Columns |
|-------|---------|
| `customers` | customer_id, first_name, last_name, email, city, country, signup_date |
| `categories` | category_id, name |
| `products` | product_id, name, category_id → categories, price, stock |
| `orders` | order_id, customer_id → customers, order_date, status (`pending`/`shipped`/`delivered`/`cancelled`) |
| `order_items` | order_id → orders, product_id → products, quantity, unit_price |

## Part A: Build the database with CloudFormation

### Step 1: Read the template

Open [`cloudformation/sql-lab.yaml`](cloudformation/sql-lab.yaml). It has four sections:

| Section | What's in it |
|---------|--------------|
| `Parameters` | Inputs you can change at deploy time: database name, admin user, engine version, min/max capacity, auto-pause delay, VPC CIDR |
| `Resources` | 7 resources: `Vpc`, `PrivateSubnetA`, `PrivateSubnetB`, `DbSubnetGroup`, `DbSecurityGroup`, `DbCluster`, `DbInstance` |
| `Outputs` | Values you need afterwards: `ClusterArn`, `SecretArn`, `DatabaseName`, `ClusterEndpoint` |
| `Metadata` | Groups the parameters nicely in the console form |

Key settings on the database cluster:

```yaml
DbCluster:
  Type: AWS::RDS::DBCluster
  DeletionPolicy: Delete            # lab only: don't keep a snapshot when the stack is deleted
  Properties:
    Engine: aurora-postgresql
    ManageMasterUserPassword: true  # password generated and stored in Secrets Manager
    EnableHttpEndpoint: true        # enables the RDS Data API
    ServerlessV2ScalingConfiguration:
      MinCapacity: 0                # pause when idle
      MaxCapacity: 2
      SecondsUntilAutoPause: 600
```

See [docs/02-cloudformation-explained.md](docs/02-cloudformation-explained.md) for a
line-by-line explanation.

### Step 2: Validate and deploy

```bash
export AWS_REGION=us-east-1
export STACK_NAME=sql-lab

aws cloudformation validate-template --template-body file://cloudformation/sql-lab.yaml

aws cloudformation deploy \
  --stack-name $STACK_NAME \
  --template-file cloudformation/sql-lab.yaml \
  --region $AWS_REGION
```

Watch progress in **CloudFormation → Stacks → sql-lab → Events**. The VPC is ready in
seconds; the Aurora cluster and instance take **10–15 minutes**.

### Step 3: Read the outputs

```bash
aws cloudformation describe-stacks --stack-name $STACK_NAME \
  --query 'Stacks[0].Outputs[].[OutputKey,OutputValue]' --output table
```

Save them for the CLI:

```bash
out() { aws cloudformation describe-stacks --stack-name $STACK_NAME \
          --query "Stacks[0].Outputs[?OutputKey=='$1'].OutputValue" --output text; }
export CLUSTER_ARN=$(out ClusterArn)
export SECRET_ARN=$(out SecretArn)
export DB_NAME=$(out DatabaseName)
```

### Step 4: Run your first query with the Data API

```bash
aws rds-data execute-statement \
  --resource-arn $CLUSTER_ARN --secret-arn $SECRET_ARN --database $DB_NAME \
  --sql "SELECT version()"
```

> If the database is paused you'll get `DatabaseResumingException`. Wait ~15–30 seconds and
> try again. `run_sql.py` retries automatically.

### Step 5: Create the tables and load the data

The Data API runs **one statement per call**. [`scripts/run_sql.py`](scripts/run_sql.py)
splits `.sql` files into statements (ignoring `;` inside strings and comments) and runs them in
order:

```bash
./scripts/02-load-data.sh
```

```
table_name  | row_count
------------+----------
customers   | 10
categories  | 5
products    | 15
orders      | 20
order_items | 32
(5 rows)
```

✅ **Checkpoint:** in the console, open **RDS → Query editor**, connect to the cluster with
*Connect with a Secrets Manager ARN* (paste `SecretArn`), database `shopdb`, and run
`SELECT * FROM customers;`.

## Part B: Learn SQL

Run each lesson from the terminal, or copy its queries into the **Query Editor**:

```bash
./scripts/run-sql.sh sql/lessons/01-select-basics.sql
```

| Lesson | File | Topics |
|--------|------|--------|
| 1 | [`01-select-basics.sql`](sql/lessons/01-select-basics.sql) | `SELECT`, aliases, `WHERE`, `AND`/`OR`, `IN`, `BETWEEN`, `LIKE`, `IS NULL`, `ORDER BY`, `LIMIT`, `DISTINCT`, calculated columns |
| 2 | [`02-aggregates.sql`](sql/lessons/02-aggregates.sql) | `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `GROUP BY`, `HAVING`, `DATE_TRUNC`, `FILTER` |
| 3 | [`03-joins.sql`](sql/lessons/03-joins.sql) | `INNER JOIN`, multi-table joins, `LEFT JOIN`, anti-joins, revenue by customer/category |
| 4 | [`04-subqueries-ctes.sql`](sql/lessons/04-subqueries-ctes.sql) | Scalar subqueries, `IN`, `EXISTS`, `WITH` (CTEs), chained CTEs, `CASE` |
| 5 | [`05-window-functions.sql`](sql/lessons/05-window-functions.sql) | `RANK`, `ROW_NUMBER`, `PARTITION BY`, running totals, `LAG`, top-N per group |
| 6 | [`06-modify-data.sql`](sql/lessons/06-modify-data.sql) | `INSERT`, `UPDATE`, `DELETE`, `RETURNING`, cascading deletes, constraints |
| 7 | [`07-views-indexes.sql`](sql/lessons/07-views-indexes.sql) | `CREATE VIEW`, `EXPLAIN`, `CREATE INDEX`, system catalogs |

A taste of lesson 3, revenue per customer:

```sql
SELECT c.first_name || ' ' || c.last_name AS customer,
       SUM(oi.quantity * oi.unit_price)  AS revenue
FROM customers c
JOIN orders o       ON o.customer_id = c.customer_id
JOIN order_items oi ON oi.order_id   = o.order_id
WHERE o.status <> 'cancelled'
GROUP BY customer
ORDER BY revenue DESC;
```

### Step 6: Transactions with the Data API

Lesson 6 changes data one statement at a time. To group statements so they **all succeed or
all fail**, use a transaction:

```bash
TX=$(aws rds-data begin-transaction --resource-arn $CLUSTER_ARN --secret-arn $SECRET_ARN \
       --database $DB_NAME --query transactionId --output text)

aws rds-data execute-statement --resource-arn $CLUSTER_ARN --secret-arn $SECRET_ARN \
  --database $DB_NAME --transaction-id $TX \
  --sql "UPDATE products SET stock = stock - 1 WHERE product_id = 1"

aws rds-data execute-statement --resource-arn $CLUSTER_ARN --secret-arn $SECRET_ARN \
  --database $DB_NAME --transaction-id $TX \
  --sql "INSERT INTO orders (customer_id, order_date) VALUES (1, CURRENT_DATE)"

# Keep the changes...
aws rds-data commit-transaction   --resource-arn $CLUSTER_ARN --secret-arn $SECRET_ARN --transaction-id $TX
# ...or undo both instead:
# aws rds-data rollback-transaction --resource-arn $CLUSTER_ARN --secret-arn $SECRET_ARN --transaction-id $TX
```

### Step 7: Parameterised queries (preventing SQL injection)

Never paste user input into SQL text. Pass it as a **parameter** instead:

```bash
aws rds-data execute-statement --resource-arn $CLUSTER_ARN --secret-arn $SECRET_ARN \
  --database $DB_NAME \
  --sql "SELECT first_name, last_name FROM customers WHERE country = :country" \
  --parameters '[{"name":"country","value":{"stringValue":"Ghana"}}]'
```

### Step 8: Practise

Work through the 10 questions in [`sql/exercises/exercises.md`](sql/exercises/exercises.md)
(each has an expected answer), then check [`sql/solutions/solutions.sql`](sql/solutions/solutions.sql).

Reset the data at any time with `./scripts/02-load-data.sh`.

## Part C: Change and delete the stack

### Step 9: Update the stack with a change set

Let's raise the maximum capacity to 4 ACUs. First **preview** the change:

```bash
aws cloudformation create-change-set --stack-name $STACK_NAME --change-set-name more-capacity \
  --use-previous-template --parameters ParameterKey=MaxCapacity,ParameterValue=4

aws cloudformation describe-change-set --stack-name $STACK_NAME --change-set-name more-capacity \
  --query 'Changes[].ResourceChange.[Action,LogicalResourceId,Replacement]' --output table
```

`Replacement: False` means the cluster is modified in place, so your data is safe. Apply it:

```bash
aws cloudformation execute-change-set --stack-name $STACK_NAME --change-set-name more-capacity
aws cloudformation wait stack-update-complete --stack-name $STACK_NAME
```

> ⚠️ Some property changes (for example `DatabaseName`) **replace** the cluster, which creates a new,
> empty database. Always read the change set before applying it to a database.

### Step 10: Detect drift

Change something outside CloudFormation (for example, add a tag to `sql-lab-vpc` in the VPC
console, or change the cluster's backup retention in the RDS console), then:

```bash
aws cloudformation detect-stack-drift --stack-name $STACK_NAME
aws cloudformation describe-stack-resource-drifts --stack-name $STACK_NAME \
  --query 'StackResourceDrifts[].[LogicalResourceId,StackResourceDriftStatus]' --output table
```

### Step 11: Clean up

```bash
./scripts/03-cleanup.sh
```

This deletes the database (no final snapshot, because of `DeletionPolicy: Delete`), the
secret, subnets and VPC. Check **CloudFormation → Stacks** shows `sql-lab` as deleted.

## Run locally with Docker (free)

Practise the SQL without an AWS account:

```bash
docker compose up -d                                   # loads schema + data automatically
docker compose exec db psql -U labadmin -d shopdb      # interactive psql (\dt lists tables, \q quits)
docker compose exec db psql -U labadmin -d shopdb -f /sql/lessons/03-joins.sql
docker compose down -v                                 # stop and delete local data
```

## Cost

| Item | Cost (us-east-1) |
|------|------------------|
| Aurora Serverless v2 while **active** | ~$0.12 per ACU-hour (0.5–2 ACUs during the lab) |
| While **paused** (idle 10+ min) | $0 compute |
| Storage + I/O | a few cents for this tiny dataset |
| Secrets Manager secret | ~$0.40/month, prorated |
| VPC, subnets, security group | free (no NAT gateway) |

A two-hour session costs **well under $1**. Delete the stack when you've finished the lab.
